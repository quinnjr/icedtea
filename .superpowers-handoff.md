# Wave A -> Wave B handoff (M2 review fixes)

Wave A owns `ui/src/css/**`, `ui/src/anim/**`, `ui/src/lib.rs`. Everything below is a
change wave B must make in files wave A may not touch. Nothing here is required for
wave A's tree to build or pass its gates — all of it is already green — but each item
is a real defect that only the paint/widget side can close.

## 1. F40 (priority) — the painter must resolve gradient stops against the LINE length

**Why.** An absolute stop position (`#f6f5f4 2px`) is a distance *along the gradient
line*, not along the box. `ui/src/paint/background.rs:294-297` builds a `LengthCtx`
whose `percent_basis` is `origin.width` and hands it to `Gradient::color_at`, so every
non-horizontal gradient with a px stop lands at the wrong fraction:
`linear-gradient(to top, #f6f5f4 2px, #fbfafa)` on a 40x20 box has a 20px line, so the
2px band should be 0.10 of it and was 0.05; on 200x34 the band collapses to 0.34px.

**What wave A added** (`ui/src/css/value/image.rs`, all `pub`, all unit-tested):

```rust
impl Gradient {
    pub fn line_length_for_box(&self, w: f32, h: f32, ctx: &LengthCtx) -> f32;
    pub fn stop_positions_for_line(&self, len_ctx: &LengthCtx, line_length_px: f32) -> Vec<f32>;
    pub fn color_at_on_line(
        &self,
        t: f32,
        ctx: &ColorCtx<'_>,
        len_ctx: &LengthCtx,
        line_length_px: f32,
    ) -> Rgba;
}
```

`color_at(t, ctx, len_ctx)` is unchanged and now delegates to
`color_at_on_line(t, ctx, len_ctx, len_ctx.percent_basis.unwrap_or(0.0))`, i.e. it
still reproduces the old (wrong-for-the-painter) behaviour, so nothing breaks until
wave B switches over.

**Required change.** In `ui/src/paint/background.rs`, at each of the three
`gradient.color_at(t, &color_ctx, len_ctx)` sites (~328, ~341, ~361):

```rust
let line = gradient.line_length_for_box(origin.width, origin.height, len_ctx);
let color = gradient.color_at_on_line(t, &color_ctx, len_ctx, line);
```

Hoist `line` next to the existing `line_for_box` call at ~304/~311 rather than
recomputing per pixel. `len_ctx` stays as it is — it is still what `em`/`rem`/`ex`
inside a stop position resolve against; only the percentage basis moves.

**Test note.** The pixel gate samples only row 19 of the fixture, which is why this
never showed up. A regression test wants a `to top` gradient with a px stop on a box
taller than one pixel, sampling a row inside the band.

## 2. F41 — delete the painter's private `radial_radii`

`ui/src/paint/background.rs:180` has a `radial_radii` that wave A has now mirrored
byte-for-byte as `pub fn icedtea_ui::css::value::image::radial_radii(shape, extent,
centre: Point, w, h, ctx)`. `Gradient::line_for_box` calls it, so the two definitions
must not drift: the sampler's `t` and this module's stop fractions are measured on the
same ending shape. Replace the private copy with a call to the exported one. (The
signature differs only in taking a `Point` centre instead of `cx, cy`.)

Separately, and *not* changed by wave A because it would have diverged the two: for an
**ellipse** with `closest-corner`/`farthest-corner`, CSS Images L3 says the radii keep
the closest/farthest-*side* ratio rather than both being the corner distance. Both
copies currently use the corner distance for both axes. Worth a follow-up finding.

## 3. F7 / F78 — `line-height: <percentage>` is now absolute at computed time

`resolve_value` resolves a `line-height` percentage against the element's own computed
`font-size` (`ui/src/css/computed.rs`), so `label { font-size: 20px; line-height: 150% }`
now reaches the text stack as `LineHeight::Length(30px)` instead of `Percent(1.5)`.

`ui/src/text.rs:954`'s `absolute_px` already accepts that, so **F78 should now pass
without a text.rs change** — but wave B should add the regression test there and
re-check `TextStyle::line_height_px`, since the F78 write-up assumed the fix would land
on the text side.

## 4. F8/F9 — shorthand `transition-property` entries now reach `anim::transition`

`ComputedStyle::transition_specs` no longer drops an entry naming a shorthand, so
`anim::transition::transitioned_props`'s shorthand-expansion branch (previously dead
code) is now live. Adwaita's `transition-property: color, background` transitions
`background-color` for the first time. Wave B may see new transitions running on widgets
that were previously static — that is the fix, not a regression.

## 5. F16 — the `font` shorthand now resets `font-width`

`Prop::FontWidth` joined `FONT_LONGHANDS` and `expand_font` sinks it alongside
`font-stretch`. `ui/src/text.rs:885`'s "font-width cannot be distinguished from unset"
problem (F77) is *not* fixed by this and is still wave B's: an explicit
`font-width: normal` still loses to `font-stretch`. The two properties are now always
written together by the shorthand, so the tie-break only matters when a longhand sets
one of them directly.

## 6. F17 — `border` now resets `border-image-*`

`Prop::Border.longhands()` went from 12 entries to 16 and `expand_border` emits the four
`border-image-*` initials. Any wave B test pinning that count needs updating; the one in
`ui/src/css/registry.rs` already is.

## 7. `MediaQuery::AlwaysFalse` was renamed

It is `MediaQuery::Unknown` now (Media Queries 4's third truth value), and there is a new
`MediaQuery::Always(bool)` for media *types*. Nothing outside `ui/src/css/parse.rs`
referenced it, but `ui/tests/` should be checked if wave B adds a media-query test.

## 8. `Keyframes::segment` returns `Option<TimingFunction>`

`ui/src/css/value/keyframes.rs`'s `segment` now reports the frame's *own* timing, or
`None` when it declares none, matching `anim::keyframes::resolve_segment`. Only its own
tests called it, but any new wave B caller must supply the animation-level fallback
(CSS initial `ease`, not `linear`).

## 9. `Stylesheet` gained fields; `StyleRule` gained `origin`

* `StyleRule.origin: u8` — the cascade layer. `append_layer` sets it; loaders need no
  change (`append_layer`'s signature is untouched).
* `Stylesheet.color_definition_orders` / `MediaBlock.color_definition_orders` —
  `Vec<usize>` parallel to `color_definitions`, kept parallel so the public pairs stay
  `(name, value)` and `ui/tests/adwaita_coverage.rs`'s `for (name, _source) in
  &definitions` keeps compiling. **Follow-up for whoever owns both files at once:** fold
  the two into a `ColorDefinition { name, value, source_order }` struct and update the
  destructuring in `adwaita_coverage.rs`.
* A rule's `source_order` is now its position among sheet *items* (rules, `@keyframes`
  and `@define-color`s share one counter), not among rules. Only the ordering was ever
  meaningful. `ui/src/css/parse.rs`'s import test is updated; check any wave B test that
  pins a literal `source_order`.

## 10. `ComputedStyle` carries a `ResolveEnv`

Used-value accessors (`padding`, `length_px`, ...) resolve `rem`/`ex` against the
environment the style was resolved under instead of `ResolveEnv::default()`. A widget
that feeds a real `ex_ratio` into `resolve` now gets it honoured at used time too.
