# M4.4 Session-lock + Idle Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add secure screen locking (`ext-session-lock-v1`) plus idle notification (`ext-idle-notify-v1`) and idle inhibition (`zwp_idle_inhibit`), proven by automated round-trip, input-isolation, locker-death, and idle tests.

**Architecture:** wlroots owns the protocol objects. The `wlr` crate adds a new topmost `Band::Lock`, drives the session-lock state machine (enforcing stay-locked-on-death + input isolation in ONE place), feeds `notify_activity` centrally from its input path, and gates idle on inhibitors. The compositor creates three globals at boot and reacts to a `session_lock_changed` callback.

**Tech Stack:** Rust; wlroots 0.20 via the `wlr` crate; `wayland-client` + `wayland-protocols`/`-wlr`/`-misc` (already harness deps) for the test clients.

**Spec:** `docs/superpowers/specs/2026-08-18-wlr-port-m4.4-session-lock-idle-design.md`

```rust
pub trait SessionLockHandler {
    /// The session's lock state changed. `locked = true` when a locker takes a
    /// lock (the compositor should suspend its own focus/layout work and stop
    /// painting normal chrome); `locked = false` only on a genuine `unlock`
    /// (never when a locker dies — the session stays locked then). Defaulted to
    /// a no-op.
    fn session_lock_changed(&mut self, locked: bool) { let _ = locked; }
}
```

- [ ] **Step 4: `create_session_lock_manager`** — double-create guard + `wlr_session_lock_manager_v1_create`, store the `NonNull`, then `wl_signal_add` a `new_lock` listener (the `on_new_session_lock::<S>` extern-C fn).

- [ ] **Step 5: `on_new_session_lock`** (backend.rs, mirror `on_request_start_drag`):
  - Set `session_locked = true`; store the `wlr_session_lock_v1` pointer.
  - Register `new_surface`, `unlock`, `destroy` listeners on the lock's events.
  - Call the handler `session_lock_changed(true)`.
  - Clear normal keyboard focus (`clear_keyboard_focus`).

- [ ] **Step 6: `on_session_lock_new_surface`** — a `wlr_session_lock_surface_v1`:
  - Read its `.output`; `wlr_scene_subsurface_tree_create(lock_band, (*lock_surface).surface)` to render it in the Lock band; store the tree keyed by output.
  - `wlr_session_lock_surface_v1_configure(lock_surface, output_width, output_height)`.
  - Register a commit listener; when every current output has a committed lock surface AND `!locked_sent`, call `wlr_session_lock_v1_send_locked(lock)` once. (Simplest correct headless approach: send `locked` once the first lock surface for each live output has been configured+committed; a single-output headless backend makes this one surface.)

- [ ] **Step 7: `on_session_unlock`** — the genuine unlock:
  - Tear down the Lock-band surface trees; clear the lock pointer; `session_locked = false`.
  - `session_lock_changed(false)`.

- [ ] **Step 8: `on_session_lock_destroy` — the SECURITY invariant.** Fires when the `wlr_session_lock_v1` is destroyed. If it was NOT preceded by `unlock` (track with a flag set in `on_session_unlock`), the session STAYS locked: keep `session_locked = true`, retain a blank Lock band covering every output (drop the dead client's surface trees but keep the band and input refusal), do NOT fire `session_lock_changed(false)`. A subsequent `new_lock` may take over. Only when unlock already ran does destroy complete the teardown.

Add `focus_lock_surface_keyboard(surface)` that sends keyboard focus to a lock surface. In `on_session_lock_new_surface`, focus the (first) lock surface. Pointer: while locked, the crate's pointer-focus/hit-test must resolve only lock surfaces — gate the hit test on the Lock band while locked.
