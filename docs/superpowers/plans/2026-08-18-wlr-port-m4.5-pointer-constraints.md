- [ ] **Step 1: Activation helper.** `pub(crate) fn update_pointer_constraint_activation(&self, focused_surface: *mut sys::wlr_surface, seat: *mut sys::wlr_seat)`: if the currently-active constraint's surface != `focused_surface`, `send_deactivated` it (and if it was LOCKED with `current.cursor_hint.enabled`, `wlr_cursor_warp_absolute`/`wlr_cursor_warp` the cursor to the hint), clear `active_constraint`. Respect the M4.4 gate: while `is_session_locked()`, do not activate (the lock surface holds focus anyway, but guard defensively).
- [ ] **Step 2: Call it from `enter_surface_under_cursor`.** After resolving the surface under the cursor (the `Some((surface, …))` / `None` branches), call `update_pointer_constraint_activation(surface_or_null, seat)`. This is the single pointer-focus chokepoint, so activation tracks focus exactly.
- [ ] **Step 3: Enforcement in `on_pointer_motion`.** Before `wlr_cursor_move(cursor, device, delta_x, delta_y)`:
  - Read `active_constraint`. If `Some(c)`:
    - **LOCKED** (`(*c).type_ == WLR_POINTER_CONSTRAINT_V1_LOCKED`): skip the `wlr_cursor_move` entirely (cursor stays put). Still emit relative motion (below). Do NOT call `enter_surface_under_cursor` for a locked pointer (no cursor move → focus unchanged), OR call it with the unchanged position (idempotent) — pick the wlroots-correct one; sway skips re-entering.
    - **CONFINED** (`_CONFINED`): compute intended `(nx, ny) = (cursor.x + delta_x, cursor.y + delta_y)`; clamp into `(*c).region` with `wlr_region_confine(&(*c).region, cursor.x, cursor.y, nx, ny, &mut cx, &mut cy)`. **RETURN-VALUE handling (corrected, from the M5 session — `wlr_region_confine` does NOT produce NaN):** the fn returns a **`bool`**. Per its contract (wlroots `region.h`): it returns **`true`** with the confined coordinates written into `cx`/`cy` when the *old* position `(cursor.x, cursor.y)` is inside the region; it returns **`false`** — leaving `cx`/`cy` **UNTOUCHED** — when the old position is not in the region. So: initialize `cx`/`cy` before the call, and branch on the return — on `true`, `wlr_cursor_warp_absolute`/`warp` to `(cx, cy)` and `enter_surface_under_cursor` at the clamped position; on `false`, do NOT read the out-params (untouched garbage) — instead **re-anchor** (Step 6 helper): the `false` arm means the *old* cursor position is outside the region, and simply "keeping it put" would **wedge the cursor forever** (every subsequent motion asks the same old-position question and gets `false` again — a client-triggerable input freeze). So on `false`, warp the cursor to the nearest in-region point via the re-anchor helper, then this and future motions confine normally. Never warp to an uninitialized out-param. (No NaN check is needed here — NaN would only come from `wlr_box_closest_point` on an empty box, which this path does not call; and the `to` coords are `cursor + a real finite motion delta`. At merge with M5, this can switch to M5's `Region::confine` wrapper, which already returns `Option` for the `false` case; keep the same "don't move on `None`" behavior.)
  - If `None`: the existing `wlr_cursor_move` + `enter_surface_under_cursor` path unchanged.
  - **Always** (constraint or not, if `relative_pointer_manager()` is `Some`): `wlr_relative_pointer_manager_v1_send_relative_motion(mgr, seat, (time_msec as u64) * 1000, delta_x, delta_y, unaccel_dx, unaccel_dy)`.
- [ ] **Step 4: Enforcement in `on_pointer_motion_absolute`.** Same shape before `wlr_cursor_warp_absolute`: LOCKED → skip the warp (cursor frozen) but compute the delta from the current cursor pos to the intended absolute pos for the relative-motion emit; CONFINED → clamp the target absolute position into the region before warping; always emit relative motion (deltas = intended − current). (An absolute event has no `unaccel` deltas in the same way; use the computed delta for both accel and unaccel, or the event's fields if present — match the struct.)
- [ ] **Step 6: Re-anchor helper + `set_region` re-anchor (prevents a client-triggerable confine freeze).** `wlr_region_confine`'s boolean keys off the *old* cursor position, so the cursor must stay inside the confine region between motions, or the `false` arm wedges it. A client can break this at will via `set_region` (shrinking/moving the region away from the cursor while the constraint is live). Add:
  - A helper `reanchor_cursor_into_region(&self, constraint: NonNull<sys::wlr_pointer_constraint_v1>)`: if the cursor is NOT inside `(*c).region` (`pixman_region32_contains_point`), warp it to a point that is genuinely inside the region, then `enter_surface_under_cursor` there.
    - **Empty-region guard first:** if the region is empty (`!pixman_region32_not_empty`), do NOT warp — there is nowhere valid to put the cursor; leave it (never feed a garbage coordinate to `wlr_cursor_warp`).
    - **Do NOT trust the extents box alone.** A pixman region is a set of rectangles and need not fill its bounding box, so `pixman_region32_extents` → clamp can land in a *hole* (inside the extents, outside the region) for an L-shaped / split region a client can send — which `contains_point` would still reject, re-wedging in that narrower case. So: clamp `(cursor.x, cursor.y)` into the extents box as a first candidate; if `pixman_region32_contains_point` says that candidate is still outside, fall back to clamping into the region's **first rectangle** (`pixman_region32_rectangles(region, &n)[0]`), which is inside the region by construction. (Rectangular regions — the common case and what most tests use — resolve on the first candidate, since a single rect's extents *is* the rect.) Warp to the resulting in-region point.
  - Fill Task 2's `on_pointer_constraint_set_region` handler: when the changed constraint is the `active_constraint`, call `reanchor_cursor_into_region(c)` so the confine invariant is restored the moment the region moves — making the motion-path `false` arm effectively unreachable in normal operation (the `false`-arm re-anchor in Step 3 is then belt-and-suspenders).
- [ ] **Step 7: Consolidate the cursor accessor (Task 2 review finding).** Task 2 added `Runtime::cursor_position()`, which is a byte-for-byte duplicate of the pre-existing public `Runtime::pointer_position()`. To avoid two divergent public accessors for the same value, make `cursor_position()` a one-line delegate: `pub fn cursor_position(&self) -> (f64, f64) { self.pointer_position() }` (single source of truth; keeps the name the tests/DbCommand reference). Do NOT duplicate the body.

- [ ] **Step 1: Locked-pointer test (Criterion 2, non-vacuous).**

```rust
/// M4.5 Criterion 2: a locked pointer freezes the cursor and the client
/// receives relative-motion deltas equal to the injected motion.
#[test]
fn a_locked_pointer_freezes_the_cursor_and_delivers_relative_motion() {
    let comp = Compositor::spawn();
    let mut vp = VirtualPointerClient::spawn(&comp.socket);
    let mut pc = icedtea_harness::PointerConstraintsClient::spawn(&comp.socket);
    // Move the pointer over pc's surface so it holds pointer focus.
    vp.motion_absolute(/* over pc's surface */); vp.frame(); vp.pump();
    // Baseline (non-vacuity): an unconstrained motion MOVES the cursor.
    let before = comp.cursor_position();
    vp.motion_absolute(/* +dx,+dy */); vp.frame(); vp.pump();
    assert_ne!(comp.cursor_position(), before, "baseline: cursor should move unconstrained");

    // Lock, then PRIME activation, then inject the test motion.
    pc.lock_pointer();
    pc.pump();
    // ACTIVATION ORDERING (important — from the T3 design): a constraint on the
    // already-focused surface activates on the NEXT motion, not on creation.
    // Enforcement (the freeze check) reads `active_constraint` BEFORE the cursor
    // move, but activation happens in `enter_surface_under_cursor` AFTER the
    // move — so the FIRST motion after lock_pointer() still moves the cursor
    // (and activates the constraint); only from the SECOND motion on is the
    // cursor frozen. So inject one PRIMING motion to activate, THEN measure.
    vp.motion(/* small delta to trigger activation */); vp.frame(); vp.pump(); pc.pump();
    let locked_pos = comp.cursor_position();
    // Now the constraint is active: this motion must be frozen.
    vp.motion(/* +dx,+dy */); vp.frame(); vp.pump(); pc.pump();
    assert_eq!(comp.cursor_position(), locked_pos, "locked: cursor must not move once active");
    let (rdx, rdy) = pc.relative_delta();
    assert!(rdx != 0.0 || rdy != 0.0, "locked: client received no relative motion");
    // delta matches the injected motion (within tolerance).
}
```

Fill the exact coordinates from the harness surface geometry and the virtual-pointer extent (mirror the M4.2 drag tests for positioning a client under the injected pointer). Use relative `vp.motion(dx,dy)` deltas for the post-lock injections (activation + freeze both key off motion events). **Activation ordering:** the priming motion above is required — a constraint activates on the first motion after creation, so measure `locked_pos` AFTER that priming motion and assert the freeze on the motion after it. **Non-vacuity:** the baseline `assert_ne!` (before lock) proves the injector moves the cursor when unconstrained, so the frozen assertion cannot pass trivially.
