# icedtea-wm — wlr port Milestone 4.4: Session-lock + Idle

Date: 2026-08-18

## Overview

M4.4 adds three interop protocols in one additive `wlr` release (0.20.20):

- **`ext-session-lock-v1`** — secure screen locking. A locker client (swaylock,
  gtklock, …) takes a lock, paints a surface per output, and the compositor
  guarantees the session is secured: only the lock surfaces render and receive
  input until the client authenticates and unlocks.
- **`ext-idle-notify-v1`** — idle notification. Clients (swayidle) ask to be
  told when the seat has been idle for N milliseconds; wlroots tracks activity
  and notifies, the compositor feeds it input activity.
- **idle-inhibit (`zwp_idle_inhibit_manager_v1`)** — a surface suppresses
  idling while it is active (a video player). The compositor gates the idle
  notifier's inhibited flag.

wlroots owns the protocol objects. The `wlr` crate drives the session-lock
state machine and a new top scene band, calls `notify_activity` centrally from
its input path, and tracks idle inhibitors. The compositor creates the three
globals at boot and reacts to a lock/unlock callback.

## Decisions of record

1. **Scope: all three protocols in one combined milestone** (`ext-session-lock-v1`
   + `ext-idle-notify-v1` + idle-inhibit), one `wlr` release, one final review,
   one merge. (User decision, 2026-08-18.)
2. **The lock's security lives in the `wlr` crate, one enforcement point.** Two
   invariants are enforced by the crate, not left to the compositor:
   (a) **stay-locked-on-death** — if the lock's `destroy` fires without a prior
   `unlock` (the locker crashed), the session stays locked (the Lock band is
   retained/blanked), never restores; (b) **input refusal while locked** — the
   crate routes keyboard/pointer focus only to lock surfaces and refuses normal
   toplevel/layer focus changes while locked. The compositor only reacts to a
   `session_lock_changed(locked)` callback (suspend its own focus/layout logic).
3. **A new topmost scene band `Band::Lock`,** above `Band::Overlay`. Lock
   surfaces render here so they cover all normal content, layer-shell included.
4. **Idle activity is fed centrally from the crate's input path.** The crate
   already dispatches pointer/keyboard/touch; it calls
   `wlr_idle_notifier_v1_notify_activity(notifier, seat)` there, so the
   compositor wires nothing per-event for idle-notify.
5. **Idle-inhibit gates the notifier.** The crate tracks active inhibitors and
   calls `wlr_idle_notifier_v1_set_inhibited(notifier, any_active)`.
6. **Split-phase publish → consume, as in M1–M4.3.** One additive `wlr`
   0.20.x release (**0.20.20**); the API-review verdict is held before the
   mechanical `cargo publish`; the compositor then bumps and consumes.
   Additive-only within 0.20.x. Development uses a temporary
   `[patch.crates-io]` and swaps to the published pin at the end.
7. **Execution: SDD.** Per-task review, final whole-branch review, merge window
   — never auto-merged. wlroots-sys integrates via a PR into `develop`.

## Architecture

### Session-lock

wlroots exposes `wlr_session_lock_manager_v1` (events: `new_lock`, `destroy`),
each `wlr_session_lock_v1` (events: `new_surface`, `unlock`, `destroy`; helper
`wlr_session_lock_v1_send_locked`; flag `locked_sent`), and each
`wlr_session_lock_surface_v1` (bound to a `wlr_output`, with a `configure`).

Crate flow:
- `create_session_lock_manager(&Display)` creates the global; the crate
  registers a `new_lock` listener.
- On `new_lock`: the session enters the *locking* state immediately (a lock
  request is honored even before surfaces arrive — the protocol requires the
  compositor to treat the session as locked at once). Register `new_surface`,
  `unlock`, `destroy` listeners on the `wlr_session_lock_v1`. Fire
  `session_lock_changed(true)` to the compositor.
- On `new_surface`: a `wlr_session_lock_surface_v1` for a specific output.
  Create a `wlr_scene_subsurface_tree`/scene surface node for it in the **Lock
  band**, size it to the output, send the surface a configure. Track one lock
  surface per output.
- When **every** current output has a committed lock surface, call
  `wlr_session_lock_v1_send_locked(lock)` exactly once (guarded by
  `locked_sent`). This confirms to the client the screen is secured.
- On `unlock`: the client authenticated. Tear down the Lock band's surfaces,
  fire `session_lock_changed(false)`, restore normal rendering + input.
- On `destroy` **without** a preceding `unlock`: **keep the session locked.**
  Retain a blank Lock band (or the last lock surfaces) covering every output;
  do **not** fire `session_lock_changed(false)`; input stays refused. A new
  locker may bind and take over. This is the security invariant.

Input isolation: while `is_session_locked()` is true, the crate's focus helpers
route keyboard/pointer only to the active lock surface and refuse
`focus_toplevel_keyboard` / `focus_layer_keyboard` (they no-op or are gated).
A new `focus_lock_surface_keyboard` sends keyboard focus to a lock surface.

### Idle-notify

`create_idle_notifier(&Display)` creates `wlr_idle_notifier_v1`. In the crate's
seat input handlers (pointer motion/button/axis, key, touch), call
`wlr_idle_notifier_v1_notify_activity(notifier, seat)`. wlroots implements the
client-facing `ext_idle_notification_v1` timers and sends `idled`/`resumed`.

### Idle-inhibit

`create_idle_inhibit_manager(&Display)` creates `wlr_idle_inhibit_manager_v1`
(events: `new_inhibitor`, `destroy`). The crate tracks the set of live
inhibitors; whenever it changes, call
`wlr_idle_notifier_v1_set_inhibited(notifier, !inhibitors.is_empty())`. v1
treats any live inhibitor as active (refinement to "inhibitor's surface mapped"
is out of scope).

### Crate additions (one additive 0.20.20 release)

- `Band::Lock` — new topmost variant above `Overlay`.
- `Runtime::create_session_lock_manager(&Display) -> Result<()>` + internal
  `new_lock`/`new_surface`/`unlock`/`destroy` handlers + the Lock-band scene
  surfaces + `send_locked` gating.
- `Runtime::is_session_locked(&self) -> bool`, `focus_lock_surface_keyboard`,
  and the input-refusal gating in the existing focus helpers.
- `SessionLockHandler::session_lock_changed(&mut self, locked: bool)` (a new
  handler method, defaulted, folded into the `Handlers` supertrait set).
- `Runtime::create_idle_notifier(&Display) -> Result<()>` + central
  `notify_activity` calls from the input path.
- `Runtime::create_idle_inhibit_manager(&Display) -> Result<()>` + inhibitor
  tracking → `set_inhibited`.
- All double-create guarded, mirroring the existing `create_*_manager` helpers;
  managers are display-owned (no `Drop`).

### Compositor additions

- `compositor/src/lib.rs` **and** `harness/src/lib.rs` (both boot paths):
  create the three globals at boot, non-fatal in production / `.expect` in the
  harness, beside the existing `create_*` blocks.
- `state.rs`: implement `session_lock_changed(locked)` — while locked, suspend
  the compositor's own keyboard-focus/layout reconciliation (the crate already
  refuses normal focus, so this mostly means not fighting it and not painting
  SSD/normal chrome); on unlock, restore normal focus to the previously focused
  toplevel.

## Testing (automated-only)

Extend `harness` + `compositor/tests/client_protocol.rs`. New harness clients:
`SessionLockClient` (binds `ext_session_lock_manager_v1`), an idle-notify
client (binds `ext_idle_notifier_v1`), an idle-inhibit client (binds
`zwp_idle_inhibit_manager_v1`).

1. **Globals advertised.** `ext_session_lock_manager_v1`,
   `ext_idle_notifier_v1`, `zwp_idle_inhibit_manager_v1` each appear in
   `advertised_globals`.
2. **Lock round-trip.** `SessionLockClient` takes a lock, receives
   `new_output`/creates a lock surface per output, attaches an shm buffer and
   `ack_configure`+commits; asserts it receives the `locked` event. Then a
   `TestClient` toplevel (mapped before the lock) is checked to **not** receive
   injected keyboard input while locked (input isolation). The client unlocks;
   assert the session restores (the toplevel can be focused again).
3. **Locker death keeps the session locked (security).** Take a lock (opt:
   reach `locked`), then drop the `SessionLockClient` without calling `unlock`.
   Assert the session remains locked: a normal toplevel still does not receive
   injected keyboard input, and `is_session_locked()` (observed via a
   `DbCommand`/harness accessor) stays true. A new lock can still be taken.
4. **idle-notify fires around activity.** Bind `ext_idle_notifier_v1`, request
   an `ext_idle_notification` with a short timeout (tens of ms). Assert `idled`
   fires after the timeout with no activity; inject pointer/key activity (via
   the M4.2 virtual-pointer / virtual-keyboard injectors) and assert `resumed`
   fires. Generous margins; activity is injected, not wall-clock-derived.
5. **idle-inhibit suppresses idle.** Create an idle inhibitor; assert the
   notifier is set inhibited (an `ext_idle_notification` does **not** fire
   `idled` past its timeout while inhibited); destroy the inhibitor; assert
   idle resumes (a subsequent notification fires).

Observability hooks the tests need (added as `#[doc(hidden)]`/test-only where
appropriate): `Runtime::is_session_locked` reachable from the harness (a
`DbCommand::SessionLocked` reply-channel command, mirroring
`DbCommand::DragIconPosition`).

**Gates:** `cargo test --workspace` + `cargo clippy --all-targets -- -D warnings`
(icedtea); `cargo test -p wlr` + clippy + `RUSTDOCFLAGS="-D warnings" cargo doc
-p wlr --no-deps` + `cargo fmt --all --check` (wlroots-sys) — green on the
freeze commit before publish.

## Success criteria

1. `ext_session_lock_manager_v1`, `ext_idle_notifier_v1`, and
   `zwp_idle_inhibit_manager_v1` are advertised (automated test).
2. A session-lock round-trip reaches the `locked` state, isolates input from
   normal clients while locked, and restores on unlock — automated, non-vacuous.
3. A locker that dies without unlocking leaves the session locked (input stays
   refused) — automated (the security invariant).
4. idle-notify delivers `idled` after an inactivity timeout and `resumed` after
   injected activity — automated.
5. idle-inhibit suppresses `idled` while an inhibitor is active and idle
   resumes when it is destroyed — automated.
6. The crate additions are semver-additive, published as one `0.20.x` release
   (0.20.20); the compositor consumes the published crate; all gates green in
   both repos; final whole-branch review clean or resolved; merge window
   presented — never auto-merged.

## Out of scope (explicit)

- Our own lock-screen UI. The compositor provides the mechanism; a locker
  client (swaylock/gtklock) provides the UI. The stay-locked-on-death fallback
  is a blank Lock band, not a login prompt.
- Suspend / DPMS / power management. idle-notify only *notifies*; acting on it
  (dim, suspend, `systemctl suspend`) is an external swayidle-style client.
- `zwp_idle_inhibit` refinement to "inhibitor surface actually mapped/visible"
  — v1 treats any live inhibitor as active.
- keyboard-shortcuts-inhibit (`zwp_keyboard_shortcuts_inhibit`) — a separate
  protocol, not part of M4.4.
- Multi-seat lock semantics beyond the single headless seat.

## Risks

- **Session-lock is security-critical.** The stay-locked-on-death invariant and
  input isolation must be airtight — a gap means the screen does not actually
  lock. Mitigation: enforce both in the crate (one place), an adversarial
  review pass on the lock state machine, and a dedicated locker-death test
  (criterion 3) plus an input-isolation assertion (criterion 2).
- **Headless lock-surface handshake.** The harness `SessionLockClient` must
  drive the full ext-session-lock client sequence (lock → get_lock_surface per
  output → ack_configure → attach+commit) before `locked` is sent. Mitigation:
  model it on the existing `TestClient` shm/configure handshake; assert
  `locked` is actually received (not just that lock() was called).
- **Idle timing tests are time-based.** Short real timeouts risk flakiness under
  load. Mitigation: generous margins, inject activity rather than depend on
  wall-clock quiescence, and single-threaded test runs (the suite already uses
  `--test-threads=1`).
- **Input-isolation completeness.** Both keyboard AND pointer must be isolated,
  and layer-shell/toplevels must not grab focus while locked. Mitigation: gate
  all focus helpers on `is_session_locked()`; the isolation test covers
  keyboard; a review checklist item covers pointer + layer.
- **New top band ordering.** `Band::Lock` must sit above `Overlay` for every
  output and be sized/repositioned on output changes. Mitigation: mirror the
  existing banded-scene handling; the round-trip test renders a lock surface
  and (optionally) a screencopy capture could confirm coverage — but the
  primary assertion is the protocol `locked` + input isolation.
