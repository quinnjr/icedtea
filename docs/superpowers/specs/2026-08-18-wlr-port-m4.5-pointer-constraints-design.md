# icedtea-wm — wlr port Milestone 4.5: Pointer-constraints

Date: 2026-08-18

## Overview

M4.5 — the last M4 sub-milestone — adds pointer constraints and relative
pointer motion in one additive `wlr` release (0.20.21):

- **`zwp_pointer_constraints_v1`** — a client asks to **lock** the pointer
  (cursor frozen in place, e.g. an FPS game or a 3D viewport) or **confine**
  it (cursor clamped to a region of a surface). The compositor activates the
  constraint when the surface has pointer focus and enforces it on the cursor.
- **`zwp_relative_pointer_manager_v1`** — delivers unaccelerated relative
  motion **deltas** to clients. This is what makes a *locked* pointer usable:
  the cursor does not move, but the client still receives motion deltas.

wlroots implements the protocol objects and the lock/confine geometry helpers;
the `wlr` crate owns the seat, cursor, and pointer-focus, so it drives
activation and the motion enforcement. The compositor only creates the two
globals at boot.

## Decisions of record

1. **Scope: all three** — locked pointer, confined pointer, and relative
   pointer. They interlock: relative-pointer is required for a locked pointer
   to be useful, and confine reuses the same machinery. (User decision,
   2026-08-18.)
2. **The `wlr` crate owns the enforcement, one place.** The crate already owns
   the `wlr_cursor`, the seat pointer focus, and the `on_pointer_motion*`
   handlers, so activation (on pointer-focus change) and motion
   suppression/clamping live there. The compositor creates the two globals and
   does nothing further — no `state.rs` routing.
3. **Activate-on-pointer-focus policy.** A constraint activates
   (`wlr_pointer_constraint_v1_send_activated`) when its surface holds the
   seat's pointer focus, and deactivates (`send_deactivated`) when focus
   leaves. This is the standard wlroots/sway policy. At most one constraint is
   active per seat.
4. **Cursor-hint-on-deactivation.** When a locked constraint deactivates and
   carried a `cursor_hint`, warp the cursor to that hint (the client's
   requested resting position), per protocol.
5. **Destroy-listener keying by the listener's own address** — apply the M4.4
   lesson: verify what `data` wlroots passes on the constraint's `destroy`
   signal, and key the removal map on the destroy listener's address
   (`Registration::listener_addr()`), not on `data`.
6. **Split-phase publish → consume, as in M1–M4.4.** One additive `wlr`
   0.20.x release (**0.20.21**); the API-review verdict is held before the
   mechanical `cargo publish`; the compositor then bumps and consumes.
   Additive-only within 0.20.x. Development uses a temporary
   `[patch.crates-io]` and swaps to the published pin at the end.
7. **Execution: SDD**, per-task review on **Opus** (user's standing preference
   this milestone-arc), final whole-branch review, merge window — never
   auto-merged. wlroots-sys integrates via a PR into `develop`.
8. **Shared-repo coordination.** The wlroots-sys repo is shared with a parallel
   session (working M5). Coordinate branch operations via SendMessage before
   any `develop` push; the `[patch.crates-io]` path resolves to whatever branch
   is checked out in wlroots-sys, so keep it on `feature/wlr-m4.5` during
   development.

## Architecture

wlroots provides `wlr_pointer_constraints_v1` (event `new_constraint`) and each
`wlr_pointer_constraint_v1` (`surface`, `seat`, `type_` = locked | confined,
`region` (pixman), `current.cursor_hint`, `lifetime`; events `set_region`,
`destroy`; `send_activated`/`send_deactivated`), plus
`wlr_relative_pointer_manager_v1_send_relative_motion(manager, seat, time_usec,
dx, dy, dx_unaccel, dy_unaccel)`.

The `wlr` crate's current pointer path (`backend.rs`):
- `on_pointer_motion` (relative): `wlr_cursor_move(cursor, device, delta_x,
  delta_y)` → new `(x, y)` → `enter_surface_under_cursor`.
- `on_pointer_motion_absolute`: `wlr_cursor_warp_absolute(cursor, device, x, y)`
  → `enter_surface_under_cursor`.
- `enter_surface_under_cursor` resolves the surface under the cursor and
  `wlr_seat_pointer_notify_motion`/`notify_clear_focus`; this is also the
  pointer-focus point where constraints activate.

### `wlr` crate additions (one additive 0.20.21 release)

- Fields in `RuntimeInner`: the two manager `NonNull`s; the currently-active
  constraint pointer (per seat); a map of live constraints' listeners keyed by
  destroy-listener address.
- `Runtime::create_pointer_constraints_manager(&Display) -> Result<()>` +
  `Runtime::create_relative_pointer_manager(&Display) -> Result<()>` — mirror
  the existing `create_*_manager` (double-create guard, display-owned NonNull).
  `create_pointer_constraints_manager` registers a `new_constraint` listener.
- `on_new_pointer_constraint`: register `set_region` + `destroy` listeners
  (keyed by destroy-listener address), store the constraint; if its surface
  already holds pointer focus, activate it.
- **Activation hook in `enter_surface_under_cursor`:** when the focused surface
  changes, deactivate the previously-active constraint (warping to its
  `cursor_hint` if a deactivating lock had one) and, if the newly-focused
  surface has a constraint for this seat, `send_activated` it and record it as
  active.
- **Motion enforcement**, in `on_pointer_motion` / `on_pointer_motion_absolute`,
  *before* the `wlr_cursor_move`/`warp_absolute`:
  - **locked active** → skip the cursor move entirely (cursor stays put).
  - **confined active** → clamp the intended new position to the constraint's
    region (intersected with the surface) using wlroots' constraint region;
    move/warp to the clamped position.
  - **always** (if a relative-pointer client is bound) → `send_relative_motion`
    with the event's accelerated and unaccelerated deltas.
- `Runtime::cursor_position() -> (f64, f64)` — a public accessor reading the
  `wlr_cursor`'s `(x, y)`, for tests to observe the cursor did/didn't move.
  (Additive; read-only.)

### Compositor additions

- `compositor/src/lib.rs` **and** `harness/src/lib.rs` (both boot paths):
  create the two globals at boot, non-fatal in production / `.expect` in the
  harness, beside the existing `create_*` blocks.
- `state.rs`: no routing change expected. A `DbCommand::CursorPosition { reply }`
  reply command (mirroring `DbCommand::DragIconPosition`/`SessionLocked`) exposes
  `Runtime::cursor_position()` to the harness for the cursor-frozen assertions.

## Testing (automated-only)

Extend `harness` + `compositor/tests/client_protocol.rs`. New harness client
`PointerConstraintsClient` (binds `zwp_pointer_constraints_v1` +
`zwp_relative_pointer_manager_v1`, maps a surface, creates a locked or confined
pointer on it, binds a `zwp_relative_pointer_v1`, captures relative-motion
events into a delta accumulator). Driven by the M4.2 `VirtualPointerClient`.
`Compositor::cursor_position()` via the new `DbCommand`.

1. **Globals advertised.** `zwp_pointer_constraints_v1` and
   `zwp_relative_pointer_manager_v1` each appear in `advertised_globals`.
2. **Locked pointer freezes the cursor + delivers relative deltas.** Map a
   client surface, move the virtual pointer over it (so it has pointer focus),
   record the cursor position; create a `locked_pointer`; inject a pointer
   motion delta; assert (a) `cursor_position()` is **unchanged** (frozen), and
   (b) the client's `zwp_relative_pointer_v1` received a relative-motion event
   whose delta equals the injected delta. **Non-vacuous:** a baseline motion
   *before* locking asserts the cursor **does** move and no relative event is
   required, so the frozen+delta assertions cannot pass trivially.
3. **Confined pointer clamps to the region.** Create a `confined_pointer` with a
   small region; inject motion toward and past a region edge; assert the cursor
   position stays within the region bounds (clamped at the boundary), rather
   than following the raw injected delta out of the region.
4. **Activation follows pointer focus.** A constraint whose surface does **not**
   have pointer focus is not active (a locked pointer over an unfocused surface
   does not freeze the cursor); moving focus onto the surface activates it.

**Gates:** `cargo test --workspace` + `cargo clippy --all-targets -- -D warnings`
(icedtea); `cargo test -p wlr` + clippy + `RUSTDOCFLAGS="-D warnings" cargo doc
-p wlr --no-deps` + `cargo fmt --all --check` (wlroots-sys) — green on the
freeze commit before publish.

## Success criteria

1. `zwp_pointer_constraints_v1` and `zwp_relative_pointer_manager_v1` are
   advertised (automated test).
2. A locked pointer freezes the cursor while the client receives relative
   motion deltas equal to the injected motion — automated, non-vacuous.
3. A confined pointer clamps the cursor to its region — automated.
4. A constraint activates only when its surface has pointer focus — automated.
5. The crate additions are semver-additive, published as one `0.20.x` release
   (0.20.21); the compositor consumes the published crate; all gates green in
   both repos; final whole-branch review clean or resolved; merge window
   presented — never auto-merged.

## Out of scope (explicit)

- Cursor-shape (`wp_cursor_shape_v1`) and pointer-warp protocols.
- Tablet-tool constraints.
- Pointer-acceleration profile selection — the crate forwards wlroots'
  accelerated and unaccelerated deltas as wlroots computes them.
- Multi-seat constraint semantics beyond the single headless seat.
- Any change to the session-lock input isolation — while the session is locked,
  the lock surface holds pointer focus, so no normal-client constraint
  activates; this falls out of the activate-on-focus policy and the M4.4 gates,
  and is confirmed in review rather than re-implemented.

## Risks

- **Motion enforcement correctness.** The lock (skip move) and confine (clamp)
  branches sit in the hot pointer-motion path. A wrong branch could freeze the
  cursor when it should not, or fail to freeze when it should. Mitigation: the
  non-vacuous locked test (baseline-moves then locked-frozen) and the confine
  clamp test; the enforcement reads the active-constraint state set by the
  focus hook, so an unfocused constraint is inert by construction.
- **Relative-motion delta fidelity.** The client must receive deltas equal to
  the injected motion. Mitigation: the virtual-pointer injects a known delta
  and the test asserts the accumulated relative delta matches (within a small
  tolerance if sub-pixel).
- **Constraint lifecycle / destroy `data`.** Apply the M4.4 lesson: do not
  assume the constraint `destroy` signal carries the constraint as `data` —
  check wlroots' `wl_signal_emit` for that signal and key the listener map on
  the destroy listener's address. Mitigation: a create+destroy (and
  client-disconnect) path is exercised so a mis-keyed listener would abort
  loudly, exactly as the M4.4 session-lock/idle-inhibit crashes did.
- **Confine region on a headless single output.** The region is in surface
  coordinates; the test places the surface and region at known coordinates so
  the clamp boundary is deterministic.
- **Interaction with the virtual-pointer injector.** The injected pointer must
  hold focus on the constrained surface for activation; the test warps the
  virtual pointer over the surface first (as the M4.2 drag tests do).
